Anime Lighthouse Index — Shipped features (reference)
======================================================

Purpose: Accurate catalogue of behaviour in the deployed static app and its
integrations. Behaviour is defined by the repo (HTML/CSS/JS) and Supabase;
this file summarizes it for onboarding and discussion. Companion docs:

- PRD.txt        — problem, intent, audience, scope, success signals
- ENHANCEMENTS.txt — backlog only (not shipped)
- SCHEMA.txt      — Postgres tables, enums, RLS
- SITUATION.txt   — why the project exists

Maintenance: bump numbers or wording here when UX or integrations change.


1. Routes (no client-side router — plain HTML + ES modules)

- / → index.html (Recent)
- /list → list.html (compact list rows)
- /about → about.html
- /sighting → sighting.html (single shared sighting; ?id= numeric sightings.id)
- /submit → submit.html (public submission; no OAuth; Edge Function queue insert)
- /submit-admin → submit-admin.html (authenticated sighting insert)
- /review → review.html (authenticated moderation of public queue)
- /submitl → submitl.html (authenticated lighthouse insert)
- /submiti → submiti.html (authenticated image reorder/upload for existing sightings; not in tab strip)
- /admin → admin.html (maintainer hub; OAuth login + links to submit tools)
- /edit → edit.html (authenticated sighting metadata update; not in tab strip)

Shared chrome behaviour is implemented in js/nav.js (Recent vs List, submit subtabs).
Footer site links (partials/footer-links.html) include Home, About, Submit, and Admin.


2. Data backend (Supabase)

Authoritative columns and policies: SCHEMA.txt.

Headlines relevant to UX:

- sightings: titles (EN / romaji / JP), date_spotted (required), optional episode &
  timestamp text, optional anilist_link, image_link text[] (public URLs), notes,
  lighthouse_type (real | fictional | unidentified; default fictional), optional
  lighthouse_id, media_type (anime | manga | other), media_id when filled via AniList.
- lighthouses: names, prefecture, external links (Wikipedia EN/JP, Maps, Lighthouse-JAPAN), notes_l.
- Storage: public-read bucket sightings-images; objects under sightings/; submit flows
  append uploaded WebP public URLs into image_link.

RLS allows world read; inserts/updates for sightings and lighthouses are restricted to the
maintainer account (see SCHEMA). js/supabaseClient.js holds the project URL and anon key;
security boundary is server policy, not UI state.


3. Browse — Recent (index.html)

- Card layout: date row (with optional direct-link icon when id is set), image(s), title (per
  title mode), episode/timestamp line, AniList link, optional real-lighthouse block, notes
  ([label](https://...) in notes renders as hyperlinks on the card).
- Direct link: top-right of the date row, Material link icon (currentColor); tooltip/aria-label
  “Direct link”; navigates to /sighting?id=<id> (same card on the share page).
- Episode/timestamp line uses trimmed fields only: no placeholder when one side is missing;
  both present join as “ep / ts”; only one present shows that value alone; whitespace-only
  values are ignored. AniList link still renders when episode/timestamp are empty.
- When image_link has more than one URL, the title row uses a two-column layout: title text
  wraps in the left column; the right column shows a small photo-library-style icon (Material-style
  glyph, inline SVG with currentColor matching --text-muted). Tooltip and aria-label on the wrapper
  still include the image count; collapsed List rows do not show the icon (only the expanded card
  from buildSightingCard).
- Multi-image: card and lightbox share index; circular on-screen prev/next buttons and
  ArrowLeft/ArrowRight; buttons hide at ends; lightbox closes on backdrop/image click or Escape.
- Re-renders from filter/sort/search/page change close an open lightbox first.
- Pagination: 10 per page; first/prev/next/last + range label; filter changes reset to page 0;
  scroll anchors to main content once after page moves.
- Page nav position: footer selector (Top / Bottom / Both), stored in localStorage
  (js/preferences.js).
- Recent card image area: `.card--recent` applies a full-width 16:10 aspect box (capped with
  `max-height: 80vh`) so layout height is reserved before the hero decodes; `overflow: hidden`
  clips the slot; the hero `<img>` is `position: absolute` inside the wrap with `object-fit:
  contain` and `max-width`/`max-height: 100%` so painting stays inside the slot (including
  portrait shots on iOS Safari).
- Hero loading: lazy on card heroes; next page’s first image per card is warmed with `Image()`
  after render (js/main.js).


4. Browse — List (list.html)

- Compact rows: one line shows active title mode (fallback title_en) in bold, optional space +
  <episode> when episode is non-empty after trim (disambiguates duplicate titles), then optional
  “ (lighthouse name en)” for real sightings; expand toggles the full card as on Recent.
- First expand builds and caches card DOM per row.
- Toolbar: Collapse All (disabled when nothing expanded), live filtered count.


4.1 Shared sighting (sighting.html)

- Query ?id= must be a positive integer sightings.id; missing, invalid, or not found → redirect
  to / (no error page).
- One card via buildSightingCard (Recent-style image slot); fetchSightingById in dataservice.js
  (not the full-list sessionStorage cache).
- Chrome: site header (Recent • List, no filter burger), footer theme + Titles only (no PAGE
  NAV), Home/About links.
- document.title updates from the loaded row and active title mode.


5. Search, filters, sort, titles, theme

- Search: case-insensitive substring across primitive fields, arrays, and nested objects on
  each row; debounced ~200 ms (js/browse/controls.js).
- Filters: media type checkboxes (anime/manga; “other” passes when either is on); “real
  lighthouses only”; lighthouse dropdown from distinct joined names.
- Filter panel footer: live filtered result count (bottom left; “N results” / “1 result”);
  Reset (bottom right) restores panel defaults — Recent: newest sort; List: A–Z — without
  changing title mode, page nav position, or theme. Reset is disabled when filters already
  match defaults.
- Sort: newest/oldest by date_spotted; A–Z / Z–A by active title field. Defaults: Recent =
  newest; List = A–Z.
- Title mode: English / Romaji / Japanese (footer); persisted in localStorage.
- Theme: dark default; light via footer switch; animelighthouse.theme + theme-boot.js in <head>
  to reduce flash.


6. Client-side browse cache

- After a successful fetch, rows are cached in sessionStorage (animelighthouses.sightings.v1)
  with TTL SIGHTINGS_CACHE_TTL_MS in js/dataservice.js. Bump the key suffix if the cached
  shape changes.


7. Submit — sighting (submit-admin.html)

- Auth: GitHub OAuth via Supabase; all controls disabled until session exists; admin-oriented
  copy when logged out; RLS is authoritative.
- Image source: label toggle Upload vs URL. URL mode is lookup-only for trace.moe and SauceNAO;
  final insert still requires a local file for the image pipeline (see ENHANCEMENTS for
  possible URL-only path).
- Fields (current vertical order): date_spotted (default today), image file + trace.moe control
  row, URL row for lookups, SauceNAO key + button row, AniList URL + Fetch, EN and romaji
  titles (required in form), optional JP title, optional episode/timestamp, Real? + lighthouse
  select when real, notes.
- Upload pipeline: input cap MAX_IMAGE_BYTES (12 MB); pica resize capped at 1920×1920;
  Web encode to WebP; path pattern sightings/<date>[_<anilist-media-id>]_<random8>.webp;
  at most one new image per insert (multi-image via submiti).
- Nulls: empty strings become null where applicable; lighthouse_type/id from Real checkbox.

7.1 trace.moe (submit)

- Upload mode: POST raw bytes to https://api.trace.moe/search?anilistInfo=1&cutBorders
  (no API key). URL mode: same endpoint with url= query parameter.
- Tiers from TRACE_HIGH / TRACE_LOW in js/pages/submit-sighting.js (currently 0.9 /
  0.75 respectively). Strong / Possible tiers show Insert; below low shows warning and
  no Insert; thumbnail still shown for feedback.
- Insert: overwrite episode + timestamp only (formatter: numeric episodes use E-prefix with
  leading zero for 0–9; non-numeric pass-through; null episode stays empty — never lone “E”);
  chained AniList GraphQL for blank titles and media_type refinement. anilist_link, media keys,
  and titles fill only when currently empty.

7.2 SauceNAO backup (submit)

- Key stored in localStorage as animelighthouse.saucenaoKey (not committed).
- Browser calls SauceNAO through Supabase Edge Function saucenao-proxy (CORS workaround);
  invokes with authenticated client (functions.invoke).
- Search constrained to Anime* index (db=21). Parsing: data.part → episode, data.est_time
  left segment → timestamp, data.anilist_id → AniList id when present. header.similarity
  vs SAUCE_HIGH / SAUCE_LOW (80 / 60) for tiering; same Insert/Clear UX pattern as trace.moe
  at a high level (episode/timestamp overwrite; other fields fill-if-empty; optional AniList
  chain).

7.3 AniList (submit)

- Parse anilist.co anime/manga URLs for numeric id; GraphQL to https://graphql.anilist.co.
- On successful submit, media_id and media_type included when available from cache.

7.4 Filename hints (submit upload)

- On valid image file select, parse file.name and overwrite matching fields when a pattern
  matches (no clear when a pattern is absent).
- Timestamp: `\d+h_\d+m_\d+s` with optional fractional seconds (ignored) → `hh:mm:ss` via
  formatTimestamp in js/pages/submit/traceMoe.js; last match wins.
- Episode: `S\d+E\d+` first (season ignored, formatEpisode); else if filename contains
  SubsPlease, ` - NN (1080p)` → formatEpisode; last match per regex. trace.moe / SauceNAO
  Insert still overwrite episode + timestamp when used.


8. Submit — lighthouse (submitl.html)

Same auth pattern. Fields for names, links, prefecture (full Japan list), notes. Optional
prefecture auto-select when pasting a lighthouse-japan.com URL whose path matches a label.


9. Public submit (submit.html)

- No OAuth. Single basic form: image URL and/or AniList media URL (at least one required;
  AniList must be anilist.co/anime/… or anilist.co/manga/…), notes, optional username, honeypot.
- Chrome: subtitle bar (Home), site footer (light-theme toggle + footer links). No staff login link.
- POST via Edge Function public-submit-sighting (verify_jwt false): honeypot, rate limit per ip_hash,
  optional silent AniList enrichment in enrichment jsonb.
- Footer link Submit between About and Admin.

10. Review submissions (review.html)

- OAuth like other admin tools. Layout like edit.html: submission dropdown, then form.
- Full metadata form (same fields as submit-admin): date, AniList + Fetch, titles, episode,
  timestamp, real lighthouse, notes. Titles prefilled from queue enrichment or AniList Fetch;
  episode/timestamp via trace.moe / SauceNAO on uploaded image or submitter URL.
- Submitter image URL (link + preview, never published); notes include Thanks {username}! when set.
- Maintainer must upload an image (Storage WebP) before Approve; submitter URL used only for
  trace.moe / SauceNAO lookup (Submitter URL toggle). Approve calls approve_sighting_submission RPC.
- Reject deletes queue row.

11. Submit — images (submiti.html)

Pick sighting (newest-first list). Reorder, mark delete, upload more with same resize/WebP
pipeline. Save updates image_link and removes Storage objects for deleted URLs.


12. Admin hub (admin.html)

- OAuth via submitAuth.js (login/logout; notice when logged out). Hub link list is hidden
  until a session exists; each tool page still gates writes.
- Links: Add sighting (/submit-admin), Add lighthouse (/submitl), Edit images (/submiti),
  Edit sighting (/edit), Review submissions (/review).


13. Edit sighting (edit.html)

- Same auth pattern as other submit-family pages (form disabled until session).
- Sighting dropdown (newest first; shared loader in js/pages/sightingSelect.js). Optional
  ?id= query pre-selects a row after load.
- Form mirrors submit metadata fields (no image upload). Save runs UPDATE on sightings
  (image_link omitted — use submiti for images).
- Stored-image section: read-only preview of image_link[0]; trace.moe and SauceNAO use URL
  mode against that URL; hint links to submiti when no image.
- AniList Fetch overwrites titles on click; media_id / media_type from cache on save.
- Subtitle: Admin, Edit images, Home (admin-subtitle pattern).


14. External dependencies (browser)

- AniList GraphQL, trace.moe search API, SauceNAO (via edge function only from the client).
- pica@9.0.1 (CDN) for resize before WebP.
- @supabase/supabase-js v2 from CDN.


15. Styling and entrypoints

- css/main.css everywhere; css/submit.css on submit*, admin.html, and edit.html.
- Module scripts per page; see file headers in js/ for page-specific behaviour.
- Shared HTML chunks live in /partials/ and are composed into top-level *.html
  by `npm run build:html` (tools/build-html.mjs). Edit a partial then re-run
  the script before committing.
