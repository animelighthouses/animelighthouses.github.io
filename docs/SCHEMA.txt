Anime Lighthouse Index — Supabase Postgres schema notes
========================================================

Purpose: Maintainer reference aligned with live project state. Last cross-checked
2026-05-09 via Supabase MCP (list_tables verbose + get_advisors). Row counts at
that snapshot: lighthouses=22, sightings=120 — they drift over time.

---

public.lighthouses
------------------
- RLS: enabled
- Primary key: id (integer, GENERATED BY DEFAULT AS IDENTITY)
- Referenced by: public.sightings.lighthouse_id

Columns (all nullable except id):
  id                    integer, identity
  name_en               text
  name_jp               text
  wiki_en               text
  wiki_jp               text
  lighthouse_japan_link text
  google_maps_link      text
  notes_l               text
  prefecture            text

---

public.sightings
----------------
- RLS: enabled
- Primary key: id (integer, GENERATED BY DEFAULT AS IDENTITY)
- Foreign key: lighthouse_id -> public.lighthouses.id (sightings_lighthouse_id_fkey)

Columns:
  id               integer, identity
  date_spotted     date (required)
  title_en         text
  title_r          text
  title_jp         text
  media_id         text
  anilist_link     text
  episode          text
  timestamp        text
  lighthouse_id    integer (nullable)
  image_link       text[] (nullable) — public image URLs after upload
  lighthouse_type  sighting_type NOT NULL DEFAULT 'fictional'
  media_type       media_type NOT NULL DEFAULT 'anime'
  notes            text

Enums:
  sighting_type: real | fictional | unidentified
  media_type:    anime | manga | other
  submission_form_mode: basic | advanced

public.sighting_submissions
---------------------------
- RLS: enabled
- Primary key: id (bigint, identity)
- Queue for anonymous public submissions; not world-readable

Columns (headlines):
  id, created_at, form_mode, username, image_url (nullable if AniList-only), anilist_link, notes,
  optional advanced metadata (date_spotted, titles, episode, timestamp, lighthouse_*,
  media_id, media_type), enrichment jsonb, ip_hash (rate limiting; not exposed to UI)

Policies:
  - SELECT / DELETE: authenticated maintainer only (same auth.uid() as sightings writes)
  - INSERT: not granted to anon/authenticated (Edge Function public-submit-sighting uses service role)

Ops: Database Webhook on INSERT → edge function notify-new-submission (Discord). See docs/SUPABASE_OPS.txt.

RPC:
  - approve_sighting_submission(submission_id, sighting jsonb) — maintainer only;
    requires non-empty image_link array (Storage URL from review upload); inserts sightings,
    deletes queue row; returns new sightings.id

---

Row-level security (policies)
-----------------------------
Policies are permissive unless you add stricter ones later.

lighthouses:
  - "Enable read access for all users"     — SELECT for role public, USING true
  - "Enable insert for authenticated users only" — INSERT for authenticated;
    WITH CHECK ties auth.uid() to the configured maintainer account (single-writer pattern)

sightings:
  - "Enable read access for all users"     — SELECT for role public, USING true
  - "Enable insert for authenticated users only" — INSERT for authenticated;
    WITH CHECK ties auth.uid() to the same maintainer account
  - "Enable update for authenticated users only" — UPDATE for authenticated;
    USING and WITH CHECK use the same maintainer account check

Reads are intentionally world-readable via the anon key. Writes rely on Auth +
these policies (not on the submit UI alone).

---

Event trigger helper: public.rls_auto_enable()
----------------------------------------------
- Type: function returning event_trigger, LANGUAGE plpgsql, SECURITY DEFINER,
  search_path fixed to pg_catalog
- Role: on CREATE TABLE / CREATE TABLE AS / SELECT INTO in schema public,
  attempts ALTER TABLE … ENABLE ROW LEVEL SECURITY so new tables do not ship
  without RLS by accident.

PostgREST / RPC exposure:
- Anyone must NOT execute this via REST. EXECUTE was revoked from PUBLIC,
  anon, and authenticated (migration name: revoke_rls_auto_enable_public_execute).
  EXECUTE remains for postgres and service_role only.

Performance notes (optional follow-ups)
-----------------------------------------
- advisory (INFO): FK sightings.lighthouse_id has no covering index; matters if
  you filter/join heavily on that column or delete many parent rows. The public
  browse flow currently loads all sightings in one query (see dataservice.js, docs/FEATURES.txt).
- advisory (WARN): INSERT/UPDATE policies use auth.uid() in a shape that can
  re-evaluate per row at large scale; Supabase docs suggest (select auth.uid())
  when that becomes measurable.
