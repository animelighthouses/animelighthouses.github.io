Enhancements (backlog only)
===========================

Items here are not committed product promises — they are ideas and future work. Shipped
behaviour is documented in FEATURES.txt; product intent in PRD.txt.


4. Bookmarkable pagination

Reflect browse page index in the URL (e.g. ?page=2 for page 2; page 0 omits query). Enables
sharing and browser back/forward alignment with paging.


7. Contact / feedback form

Lightweight public message table (text; optional name/contact). Anti-abuse measures; email
notifications to maintainer.


8. Optional media normalization

Dedicated media table keyed by AniList id — fewer repeated fetches; room for richer media
metadata. Evaluate friction for sightings without AniList linkage (fallback UX).


9. Preserve List expansion state when changing footer settings

The List view (list.html) has no pagination today; instead, rows can be
expanded into full sighting cards. Toggling unrelated preferences (theme, title
mode) should not collapse the currently expanded rows. Currently every footer
control change calls back through bindCommonControls -> renderIndexView which
clears the `expanded` set first.

Changing preferences on index.html also reset pagination (returns to page 0). This should not happen, so avoid resetting page position when toggling unrelated preferences on index.html.


11. Schema split exploration (separate tables for anime vs manga sightings)

Separate tables to drop media_type ambiguity and optionally use chapter vs episode fields;
evaluate submit complexity and incomplete-metadata cases.

- Cons: submit button becomes more complex; relies on AniList url to determine which table it needs to be added to; would need to add media type dropdown to submit form for when anilist link isnt available (possibly fallback general url).
